# Утилита проверки контрактов AsyncAPI 3.0

## Текущее состояние проекта

### Архитектура системы

Утилита представляет собой модульную систему для проверки совместимости контрактов между потребителем и провайдером на основе спецификаций AsyncAPI 3.0.

#### Основные компоненты:

1. **config.go** - Конфигурация и парсинг YAML файлов
2. **contract_validator.go** - Центральный валидатор контрактов и формирование итогового сообщения
3. **channel_validator.go** - Основная логика проверки совместимости каналов
4. **message_validator.go** - Валидация структуры сообщений
5. **main.go** - Минималистичная точка входа приложения (34 строки)
6. **protocols.yml** - Словарь протоколов AsyncAPI 3.0
7. **Тестовые файлы** - Полное покрытие тестами

### Реализованная функциональность

#### ✅ Базовая функциональность:
- Загрузка и парсинг конфигурации из YAML файлов
- Поддержка локальных и удаленных спецификаций AsyncAPI
- Проверка совместимости каналов по адресам
- Нормализация адресов с параметрами
- JSON отчеты о совместимости
- Настраиваемые уровни логирования

#### ✅ Система валидации протоколов:
- **Словарь протоколов AsyncAPI 3.0** (21 протокол по 6 категориям)
- **Строгая валидация** - неизвестные протоколы генерируют критические ошибки
- **Fallback логика** для обратной совместимости
- **Категории протоколов:**
  - Web: `http`, `ws`, `wss`, `mercure`
  - Messaging: `amqp`, `amqp1`, `jms`, `stomp`, `nats`, `solace`, `ibmmq`
  - Streaming: `kafka`, `kafka-secure`, `pulsar`
  - IoT: `mqtt`, `mqtt5`
  - Cloud: `sns`, `sqs`, `anypointmq`, `googlepubsub`
  - Caching: `redis`

#### ✅ Система валидации структуры сообщений:
- **Универсальный поиск сообщений** через операции AsyncAPI (send/receive)
- **Валидация совместимости** между потребителем и провайдером
- **Проверка полей headers и payload** с типами и обязательностью
- **Логика сервис-провайдера** - требования провайдера должны выполняться потребителем
- **Поддержка request-reply паттерна** - полная валидация асинхронного взаимодействия
- **Разбиение на логические блоки** для удобства сопровождения

#### ✅ Предохранители безопасности:
- Обязательная проверка ссылок на серверы в каналах
- Валидация протоколов как у потребителя, так и у провайдера
- Детальные сообщения об ошибках на русском языке

### Ключевые особенности

1. **Модульная архитектура** - четкое разделение ответственности
2. **Строгая валидация** - неизвестные протоколы → критические ошибки
3. **Подробные отчеты** - JSON и консольный вывод
4. **Многоуровневое логирование** - debug, info, warn, error
5. **Fallback логика** - обратная совместимость
6. **Русскоязычные сообщения** - понятные описания ошибок

### Архитектурные решения

#### Протокольная валидация:
- **Централизованный словарь** в protocols.yml
- **Строгое соответствие** - требуется точное совпадение протоколов
- **Раздельная проверка** потребителя и провайдера
- **Генерация breaking changes** вместо warnings для критических ошибок

#### Обработка ошибок:
- **Предохранители** - проверка обязательных полей
- **Детальные сообщения** с указанием конкретных проблем
- **Severity levels** - high для критических ошибок
