## Технические вызовы

### 1. Парсинг AsyncAPI 3.0 спецификаций
**Проблема:** Сложная структура вложенных ссылок между channels, operations и components  
**Решение:** Создание рекурсивной функции extractMessage для обработки различных типов ссылок

### 2. Сопоставление каналов
**Проблема:** Необходимость найти совместимый канал поставщика по протоколу и структуре сообщений  
**Решение:** Алгоритм сравнения required полей в payload сообщений

### 3. Экранирование имен каналов
**Проблема:** Слэши в именах каналов экранируются как ~1 в JSON Pointer  
**Решение:** Функции escapeChannelName и unescapeChannelName

## Архитектурные решения

### 1. Модульность
- Создание отдельного пакета `channel` для валидации каналов
- Четкое разделение ответственности между функциями
- Возможность легкого расширения функционала

### 2. Обработка ошибок
- Явное возвращение ошибок из всех функций
- Информативные сообщения об ошибках
- Graceful handling недоступных данных

### 3. Гибкость конфигурации
- Структура Config для настройки валидации
- Поддержка различных путей к спецификациям
- Возможность указания конкретного канала потребителя

- Четко определить требования
